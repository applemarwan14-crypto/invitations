# نظام الدعوات وبوابة الدخول

دعوات بصور فيها QR خاص لكل ضيف ← ترسلها بالواتساب ← الموظف يمسحها عند البوابة ← وأنت تتابع كل شي مباشرة.

![نموذج دعوة](docs/sample-invitation.png)

## التقنيات
React 19 + Vite + Tailwind 4 + مكوّنات بأسلوب shadcn/ui · Supabase (قاعدة البيانات وتسجيل الدخول) · qr-code-styling · qr-scanner · Framer Motion · Sonner · Lucide · Recharts · JSZip · PapaParse · خطوط IBM Plex Sans Arabic وReem Kufi وAmiri (مستضافة داخل الموقع نفسه).

كل الإصدارات مثبّتة في `package.json`، وسياسة CSP تنحقن تلقائياً وقت البناء (`vite.config.ts`).

## الصفحات
| الرابط | لمين | وش فيه |
|---|---|---|
| `#/login` | الكل | تسجيل الدخول |
| `#/admin` | المدير | المتابعة المباشرة، الضيوف (إضافة/CSV/تعديل/إلغاء/حذف)، الصور (فردي/ZIP)، واتساب، تصميم الدعوة، الموظفين |
| `#/scan` | المدير والموظف | المسح بالكاميرا، شاشة كاملة 🟢/🔴 مع صوت واهتزاز، وبحث يدوي بالاسم |

## قاعدة البيانات (Supabase — مشروع `invitations`)
- `profiles`: المستخدم، الدور (`admin`/`staff`)، `is_active`. أي حساب جديد يبدأ **موظف موقوف**.
- `invitations`: كود 16 حرف يتولد داخل القاعدة بمولّد آمن (`gen_random_bytes`)، الاسم، الجوال، `allowed`، `entered`، `status`.
- `scans`: كل محاولة: الدعوة، الموظف، الوقت، النتيجة، عدد الداخلين.
- `event_settings`: نصوص وألوان الدعوة ورسالة الواتساب.

**دوال البوابة** (الموظف ما يلمس الجداول أبداً):
- `scan_invitation(code)`: تتحقق وتسجّل المحاولة، وترجع الاسم والعدد فقط.
- `admit_guests(code, count)`: تقفل الصف (`FOR UPDATE`) وتتحقق ثم تزيد العدد في عملية وحدة، فيستحيل يتكرر الدخول.
- `search_invitations(q)`: بحث الطوارئ بالاسم، بدون الجوالات.

**RLS** مفعّل على كل الجداول: المدير له كل الصلاحيات، والموظف عن طريق الدوال فقط، والزائر بدون دخول ما له أي صلاحية.
**Edge Function** `manage-staff`: إنشاء حسابات الموظفين وحذفها وتغيير كلمات مرورها. مفتاح `service_role` يبقى داخل Supabase وما يوصل للمتصفح.

الملفات: `supabase/migrations/` و`supabase/functions/manage-staff/`.

## خطوات التشغيل (مرة وحدة)

### 1) Supabase (جاهز ✅)
- حساب المدير `apple.marwan14@gmail.com` جاهز ومفعّل. **غيّر كلمة المرور المؤقتة** من لوحة Supabase ← Authentication ← Users.
- التسجيل العام مقفول من قاعدة البيانات: أي حساب ما أنشأه المدير من صفحة **الموظفون** ينرفض. وللاحتياط، اقفل **Allow new users to sign up** من Authentication ← Sign In / Providers.
- حط رابط GitHub Pages في Authentication ← URL Configuration ← Site URL.
- فعّل التحقق بخطوتين (2FA) على حسابك في Supabase وفي GitHub.

### 2) GitHub Pages
```bash
git remote add origin https://github.com/<user>/invitations.git
git push -u origin main
```
بعدها من **Settings → Pages → Source** اختر **GitHub Actions**. كل `push` على `main` ينشر الموقع تلقائياً على:
`https://<user>.github.io/invitations/`

> `.env.production` فيه رابط المشروع والمفتاح العام (publishable) فقط، وهذا آمن لأن الحماية كلها من RLS. **لا تحط** مفتاح `service_role` أو `secret` في المستودع.

### 3) الموظفين
من لوحة المدير ← **الموظفون** ← **موظف جديد**. يتولد للموظف إيميل وكلمة مرور عشوائية، انسخها وأرسلها له بشكل خاص.

## قائمة الاختبار قبل الإطلاق
- [ ] دعوة سليمة ← 🟢 ودخول
- [ ] مسح نفس الدعوة مرة ثانية ← 🔴 «مستخدمة»
- [ ] دعوة ملغاة ← 🔴 «ملغاة»
- [ ] عائلة من 4 تدخل على دفعتين (2 + 2)
- [ ] صورة وصلت عبر واتساب (مضغوطة) ← تنمسح بنجاح
- [ ] آيفون (Safari) وأندرويد (Chrome)
- [ ] Supabase ← **Advisors → Security Advisor**. تحذير «SECURITY DEFINER» على الدوال الثلاث مقصود، لأن كل دالة تتحقق من دور المستخدم قبل أي شي.

## قبل المناسبة بيوم
- تأكد إن مشروع Supabase شغّال وما توقف (المشاريع المجانية تتوقف بعد أسبوع بدون استخدام).
- صدّر نسخة احتياطية من زر **نسخة احتياطية** في صفحة الضيوف.
- افتح `#/scan` على جوال الموظف ← «إضافة إلى الشاشة الرئيسية» ← سجّل دخوله.
- جهّز باور بانك، وجرّب مسح دعوة.
- **لا تعدّل أي شي في الكود يوم المناسبة.**

## بعد المناسبة
صفحة الضيوف ← **مسح الجوالات**.
